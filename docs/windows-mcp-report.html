1 What is it?

The Windows MCP Server lets an AI assistant (VS Code, Claude Desktop, custom agents) — or a programmatic SaaS backend — manage local & remote Windows hosts and Windows 365 Cloud PCs in natural language, with a live, normalized view of the whole fleet. Instead of hopping between PowerShell, the Intune portal, and the Windows 365 console, an operator asks a question and the assistant calls vetted, validated, audited tools.

18 Security model

Arbitrary PowerShell is powerful and dangerous, so guardrails are mandatory, not optional. Every tool call flows through the same enforcement point.

Risk-aware execution gate

A pre-execution analyzer scores each call's blast radius and selects a disposition. For powershell_run it statically analyses the script; declarative tools use their mutating/destructive metadata.

Tool call → Risk gate · score → read → allow mutate / destructive → confirm irreversible → confirm @ high score → Audit record

Transport & network controls

  • OAuth 2.1 or bearer auth on the HTTP transport — per-integration tokens or validated JWTs (401 without a valid credential).
  • Loopback binding (127.0.0.1) by default; public bind is explicit opt-in.
  • Host-header validation to prevent DNS-rebinding attacks.
  • Open /health probe; all MCP traffic on /mcp is authenticated.

Execution & governance controls

  • Encoded commands — never string-concatenated into a shell line.
  • Hard timeouts with full process-tree kill on expiry.
  • Confirm-gating & dry-run preview for every state-changing tool.
  • Redaction-aware audit trail — tool, args, caller, tenant, status, duration.
  • Per-principal allow-list (least-disclosure: unauthorized tools are not even exposed) & per-tenant quotas / rate limits.
Multi-tenant SaaS auth (P-SaaS). Every HTTP caller is resolved to a single principal — from a per-integration bearer secret or a validated OAuth 2.1 JWT (issuer / audience / signature via JWKS). The principal carries its tenant, tool allow/deny policy, and quota, so one server safely serves many tenants: third-party integrations are denied arbitrary-execution tools by default, a multi-tenant Entra app resolves Graph credentials per tenant, and audit + quotas are partitioned per tenant. The stdio transport runs as a full-trust local operator.

19 Architecture

A layered design: transport and auth are swappable, the core enforces cross-cutting concerns once, and every platform plugs in as a provider with no core changes.

MCP client / SaaS backend → Transport
stdio · Streamable HTTP · agent broker · /onboarding/callback → Core
registry · config · audit · risk gate · reporting · onboarding · auth → Providers
Local · Windows 365 · Remote · AWS WorkSpaces · AVD · Citrix · Horizon · Horizon Cloud · Workspace ONE UEM

Core

PowerShell engine, risk gate, audit logger, typed errors, zod config (fail-fast), and a tool registrar that wires allow-listing, confirm-gating, audit, and error mapping in one place.

Provider model

IPlatformProvider + registry, with optional capability interfaces (settings, telemetry, OnboardingCapable) that providers opt into; the core detects them at runtime.

Transports

stdio for a single local client; Streamable HTTP for remote / multi-client / SaaS use, with per-session servers and graceful shutdown.

21 Getting started

Requires Node.js ≥ 18.18 and Windows with PowerShell 7 or Windows PowerShell 5.1 for the local provider.

# Install & build
npm install
copy .env.example .env   # then edit .env
npm run build

# Run over stdio (local AI client)
npm start

# Run over Streamable HTTP (remote / multi-client / SaaS)
$env:MCP_HTTP_TOKEN = "your-secret-token"
npm run start:http

# Verify: build + lint + tests
npm run build; npm run lint; npm test
VS Code wiring included. A sample client configuration lives in .vscode/mcp.json; once built, VS Code can launch the server over stdio directly.

The MVP is shipped and verified. Later phases extend coverage without re-cutting the core abstractions.

P0 Scaffold & core — config, logger/audit, server + registry, both transports + auth. Shipped
P1a Local Windows provider — PowerShell engine, WMI, 12 tools. Shipped
P1b Windows 365 provider — Graph client, 10 Cloud PC tools. Shipped
P1c Hardening — audit wiring, timeouts, destructive-op gating, tests, docs. Shipped
P2 Remote Windows — WinRM and SSH, per-target selectable. Shipped
P3 VDI / DaaS — five platforms shipped: AWS WorkSpaces, Azure Virtual Desktop, Citrix DaaS, Omnissa Horizon, and Horizon Cloud next-gen (inventory, power, maintenance, session control). Horizon image recompose is live; broader image rollout lands with orchestration. Shipped
P-Report Real-time reporting — normalized telemetry, time-series store, resource subscriptions, threshold alerts. Shipped
P-Onboarding Self-service onboarding — least-privilege grant plans per platform, one-click Entra admin-consent URL + /onboarding/callback, and live grant verification. Programmatic app-creation path deferred. Shipped
P-SaaS SaaS-grade — OAuth 2.1 JWT + per-integration bearer principals, per-tenant Graph credential resolution, per-principal allow-list (least-disclosure) & per-tenant quotas / audit. Horizontal scaling / shared session store deferred. Shipped
P-State State portability — substrate-agnostic capture/restore, encrypted StateBundle, fidelity manifest (settings tier). USMT/FSLogix bulk-data deferred. Shipped
P-Migrate Cloud transformation — traditional / VDI → Windows 365 migration orchestrator: plan → provision → capture → restore → verify, async with source retention. Shipped
P-Failover Cross-substrate continuity — health-triggered failover & fail-back between substrates, telemetry-informed, with state rehydration. Async, gated, audited. Shipped
P-Agent Client troubleshooter agent — outbound broker, enrollment + attestation, autonomy ladder (L0–L3), self-verifying remediation with auto-rollback. mTLS hardening & edge telemetry later. Shipped
P-MultiOS Beyond Windows — Workspace ONE UEM manages iOS / Android / Windows / macOS devices today; Intune MDM and Linux (SSH) providers are next. Partially shipped
